# ADR-0002: 视觉语言基线 v0.3（Soft Midnight 设计契约）

- 状态：Accepted
- 日期：2026-06-13
- 决策者：hashmike + Claude Code
- 涉及层：docs（前端视觉契约，约束三层页面）

## 背景

`数字资产投资操作系统_视觉说明.html`（v0.2）确立了 Soft Midnight 风格基线，方向正确，但作为多 agent 的施工契约存在三类问题：

1. **概念错误**：市场状态字段写成 `Risk-On`，与项目定义的客观信号语言冲突——`risk-on/risk-off` 在立项书里是「美股宏观」输入维度，不是 Phase 1 输出状态。Phase 1 输出为多维信号原子，旧版综合状态词表若未来使用，也只能作为信号原子之上的合成层。
2. **token 不自洽**：色板 `App BG #060A10` 与 `:root --bg #070b12` 不一致，`--panel/-2/-3` 命名未进色板，导致没有唯一可信色值源。
3. **设计语言缺承诺**：本产品区别于模板工具的几样东西——快照可证伪、基准可淘汰、AI 可回测、记录不中断——只在文字里点名，未进入视觉语言。

PRD 2 明确「页面具体视觉在子 PRD 细化」，故真实整页 mockup 不在本轮范围；本轮只把**设计语言级**的承诺在风格说明里定死。

## 决策

将视觉说明升级为 v0.3，范围 A+B+C（真实整页 mockup 延后到子 PRD）：

- **语言基调**：中文主、术语英文（ETF / TWR / MWR / Snapshot 等保留英文，状态与标签走中文）。
- **A 纠错**：市场状态字段改为信号原子语言，不再使用 `Risk-On` 作为系统输出；token 全量取自 `:root`——色板展示语义主色，并附**完整 token 清单**（表面 / 描边 / 文字 / 强调色 + 圆角 / 阴影），消除色板与变量的不一致与 overclaim；涨跌「不只靠颜色」（配 +/− 或箭头）写成明文规则。
- **B 设计语言范式**（新增示意小节）：
  - 快照冻结态——回放/已锁定视觉语言，区别于实时数据，是「可证伪肉眼验证入口」的视觉根；
  - 策略 vs 基准双曲线——实/虚线区分、超额区间着色、TWR/MWR 并列；
  - AI/规则来源标记规范——AI 来源挂「模型」徽章 + 准确率回测角标，数据规则信号不挂，界面与存储一致（呼应立项书第十节）；
  - 信号历史时间线——含滞后/防抖呈现；
  - 错误/陈旧/空/加载态进组件库——呼应「最常见的死法是记录中断」。
- **C 差异化组件占位**：资产池 T0–T4 徽章；对账差异 + 待归属队列态；执行偏离标记；站内动态 / 未来推送卡片信息结构（绝不含账户敏感信息）。

## 备选方案

- 只做 A（纠错）：被否，token 修了但产品最独特的几块屏仍无视觉语言，多 agent 无对齐基准。
- A+B+C+D（连四页高保真 mockup）：被否，与子 PRD 的页面细化重叠，且违反「先骨架后加宽」。
- 维持英文界面：被否，面向中文个人用户，定中文主基调。

## 影响

- **职责分工**：`design/数字资产投资操作系统_视觉说明.html` 是 agent 做前端时**直接参照的契约源**（抄 token / 组件 / 状态词表）；本 ADR 是其**决策依据**（记录为什么这样定、否决了什么）。前者用来抄，后者用来不踩已拍板的坑。
- `design/数字资产投资操作系统_视觉说明.html` 成为唯一可信的 token / 组件 / 状态词表来源；后续子 PRD 的页面设计据此展开，不得另起一套。
- **接入治理**：在 `AGENTS.md` §0 权威文档加入视觉契约指针，并在 §5 派活模板提醒「涉及前端/视觉先读视觉契约与本 ADR」——否则本 ADR 写得再好也不保证后续 agent 自动读到。
- 信号层子 PRD 须沿用信号原子语言与 AI/规则标记规范；策略层子 PRD 须沿用基准双曲线与 TWR/MWR 呈现；账本层子 PRD 须沿用错误/陈旧/对账/待归属态。
- v0.2 风格基线不删除，被本 ADR 细化。后续若推翻本基线，写新 ADR 并将本 ADR 标 Superseded。
