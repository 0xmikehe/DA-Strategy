# ADR-0003: 账本层账户模型与同步架构

- 状态：Accepted
- 日期：2026-06-15
- 决策者：hashmike + Claude Code
- 涉及层：ledger（事实层 · 账户事实库）；对 strategy / signal 有接口影响

## 背景

账本层要把 Binance 账户事实自动同步进来，并支撑策略级复盘。立项书 §5.2 与总 PRD §3.1 把「软件虚拟账本」（在交易所单一余额上软件切分多策略持仓）列为优先级最高的设计议题。

讨论中提出改用 **Binance 物理子账户**承载策略；并完成了一份 API 调研（`docs/research/binance-account-api-research.md`，抽检 4 个接口与官方文档逐字一致）。调研暴露出：① master key 读不到子账户 Spot 成交明细（已实测确认，需每个子账户独立只读 key）；② 除成交/充提/划转外，Convert / Dust / Dividend / 钱包划转也会改变余额，漏记则对账不平。

## 决策

### 账户拓扑

- **主账户 master = 纯资金池 / 稳定币总储备 / 入金口 / 子账户查询入口，不承载策略交易。**
- **1 个实盘策略 = 1 个 Binance 子账户**（物理隔离）。
- Phase 1 实盘策略上限 = Binance 普通用户子账户额度（按当前理解为 5；以 API 实测为准）。
- 观察 / 纸面 / 研究态策略**不占**子账户名额（其归属走虚拟归属兜底，见「保留能力」）。

### 事实模型

- **事件流是唯一真相**：只追加、不可改；纠错用**冲正（reversal）**，不删改原记录。
- **账户余额、策略持仓均为派生投影**（增量计算，可从事件流重建），不单独存为「真相」。
- **守恒不变式**：对任意资产，`Σ各账户计算余额 = Σ各策略各 lot 剩余 + 主账户未分配`。用于对账与归属完整性自检。
- **成本基础存 lots（批次），卖出按 FIFO** 扣减；加权平均可由 lots 派生。

### 成交归属

- 归属由 `子账户 → 策略` 绑定**自动推导**（成交发生在哪个子账户即属哪个策略 + 当时版本）。
- **待归属队列仅用于异常**：下单到错误子账户、或外部钱包手工录入的交易。

### 两层现金流（供绩效计算）

- 对全系统：仅 **充值 / 提现** 跨边界。
- 对单个策略：**主 ↔ 子账户划转 = 策略注资 / 撤资**。
- 账本层只负责「记准现金流事实」；TWR / MWR 计算归策略层。

### 事件 taxonomy

成交、充值、提现、划转、冲正，**外加会改变余额的**：Convert（闪兑）、Dust（小额转 BNB）、Dividend（分红 / 空投）、Wallet-transfer（Spot↔Funding↔Earn）。

### API key 与绑定功能

- 每个子账户配**独立只读 key**（跑 `myTrades` / `account`）；master key 跑子账户发现 / 余额 / 主子划转 / 充值历史。
- 新增**绑定功能**：维护 `策略 ↔ 子账户(subUserId/email) ↔ 只读 key` 三元组，产出同步管道的路由表。
- 绑定时过**安全闸门**并定期复检：`enableReading=true`、`enableWithdrawals=false`、`enableSpotAndMarginTrading=false`（任一不满足 BLOCK）；`ipRestrict=true`（否则 WARN）。

### 密钥存储

- 明文 secret 存 **`.env`（gitignored）**；DB / git 内只存 `key_ref`（环境变量名），绝不存明文。
- 入库一份 `.env.example`（仅变量名）；`.env` 设 `chmod 600`。
- 经 `key_ref` 抽象，日后可换 Keychain / 1Password 而不动绑定逻辑。

### 决策时点快照（边界澄清）

- 快照的**容器**归账本层（存储 + 按 id 取回）；**内容**（市场输入维度）归信号层。
- 成交绑定 `snapshot_id`。
- 命名区分：`account_balance_snapshot`（对账用的定期余额拉取）≠ **决策时点快照**（市场输入）。

## 备选方案

- **软件虚拟账本（原 PRD 方向）**：被**降级**。物理子账户让归属 / 对账几乎白送，Phase 1 更简单；虚拟归属能力**保留**给外部钱包持仓与纸面策略（Phase 2）。
- **加权平均成本**：不选；lots 可还原最细，反向不行。
- **单一 master key 读所有子账户成交**：实测不可行。
- **密钥存 Keychain / 1Password / KMS**：Phase 1 暂缓，`.env` 起步 + `key_ref` 抽象可后换。

## 影响

- 这**修订了** PRD 中「软件虚拟账本 = 最高优先级」的定位（改为物理子账户优先）。2026-06-19 已将立项书 / 总 PRD 回写为物理子账户优先、虚拟归属兜底的统一口径。
- 账本层 PRD 据此撰写：新增绑定功能章节、扩展事件 taxonomy、补 `snapshot_id` 与外部交易手工录入。
- 同步管道需支持按 symbol 切片、分页、游标、幂等与时间窗口约束（见调研 §6）。
- **待实现阶段确认**：A1（子账户数量上限）、A2（主账户不交易约束）、A4（子账户间划转即时免费）；子账户间直接划转 Phase 1 禁止，若发生须人工复核。
- 信号层 PRD 负责定义快照内容 schema；账本层提供容器与绑定 ID。
