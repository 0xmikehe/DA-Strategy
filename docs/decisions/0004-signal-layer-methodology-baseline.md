# ADR-0004: 信号层方法论基线（信号注册表 · 卡片同源 · 三态生命周期 · AI 边界）

- 状态：Accepted
- 日期：2026-06-15
- 决策者：hashmike + Claude Code
- 涉及层：signal（判断层）；对 strategy 消费接口与账本快照存储有影响

## 背景

信号层（判断层）即将进入子 PRD 撰写。讨论中先于具体信号，达成了一套**方法论**：信号会随时间不断累积，若不先把「信号怎么定义、怎么落地、怎么展示、怎么淘汰」框死，功能一多就会忘记当初为什么这么设计，可证伪/可复盘/可淘汰的信条会被慢慢侵蚀。

本 ADR 把这套方法论定死，作为信号层每一次开发的共同地基。具体的市场状态标签、阈值、维度选型不在此 ADR，归信号层 PRD 与各信号档案。

核心信条（贯穿全项目）：**系统中不存在不被复盘检验的模块（含 AI）**。

## 决策

### 1. 信号是什么：客观市场指标，生产与消费分离

- **信号 = 关于市场的客观事实**（不依赖谁、不依赖持仓多少都成立），例如 `btc_trend_structure ∈ {上升, 震荡, 下降}`。
- **信号层对账户事实库零依赖**（红线）：市场状态不受个人持仓影响，杜绝「重仓所以看多」的污染。
- **生产与消费分离**：信号层只**生产**客观事实；「该买/该减仓/阈值多少」属**策略层**的解读，不进信号层。不同策略的差异在于**挑选并配置同一批信号原子**，而非各自要求专属信号——信号库不因新增策略而膨胀。
- 信号层是**多维独立信号原子的库**，可不断累积；综合状态（若做）只是其上一个可选的合成层。（取代「单一综合市场状态」的早期设想。）

### 2. 信号注册表 = 唯一真相源

- 每个信号在**注册表**登记：id、可证伪定义与阈值、数据源、版本、生命周期状态、回测口径、取值域。
- **代码按注册表跑，页面按注册表显示**——一处定义，两处消费，杜绝「页面写 70、代码跑 65」的漂移。（与账本层「事件流唯一真相」同一种洁癖。）

### 3. 配置页：一信号一张「同源 spec 卡片」，不做通用字段渲染

- Phase 1 信号**不能从页面增删改**，全部 hard code。每个信号在页面上是**一张专属 spec 卡片**，因各信号的判定条件/数据源差异很大，逐个手写卡片比设计一套通用字段系统更接地气。
- **卡片 spec 与判定代码同模块、同处、同时改**：一个信号 = 一个模块，导出「判定函数」+「卡片 spec」，页面渲染该模块导出的 spec → 天然不漂移。
- **纪律**：卡片上的活数字（阈值、当前状态、上次触发时间）**禁止手抄**，必须引用代码里的常量/状态；描述性文字（假设、设计理由）可自由手写。

### 4. 生命周期：三态，可审计

- **观察（影子）**：照常计算、照常进快照，但不推送、不被策略消费——新信号的试用期，用于先攒回测数据。
- **启用**：计算 + 进快照 + 推送 + 可被策略消费。
- **关闭/淘汰**：停止计算；档案不删，只追加淘汰原因。
- 状态切换是 Phase 1 信号层**唯一**一处运行时可变状态：必须**落库 + 可审计**（谁、何时、为何切换），调性同账本层 audit。

### 5. 快照：记录「活跃信号集 + 各取值 + 触发时间」

- 信号层唯一的写是**决策时点快照**（存储机制借账本层）。
- 快照在「信号层做一次市场状态判定」时产生，**节奏由市场驱动，与用户是否交易解耦**；成交记录只**指向**当时已存在的快照 ID（账本 ADR-0003 / 总 PRD §1.4 契约4），不创建快照。
- 快照须存**当时的活跃信号集 + 各自取值 + 触发时间**（不只取值）——否则信号开关变动后，历史快照会出现「当时这个信号到底开没开」的歧义，回测时间轴断裂。
- 区分两类「触发条件」：**信号判定条件**（什么数据规则把信号判成某值，属信号定义）vs **快照触发节奏**（多久跑一次判定、何时落快照，属运行参数）。二者都要在配置页可见。
- 本决策回填账本层 PRD §7.6 的快照体量开放问题。

### 6. AI 的边界：可当被回测的选手，不当定规则的裁判

- **角色 A（允许）**：AI 作为**信号源之一**（如 AI 情绪信号），输出值即一个信号原子，与其它信号一样入库、一样被回测准确率、不准则淘汰。
- **角色 B（Phase 1 禁止）**：AI 作为**元设计者**——替人决定追踪哪些信号、生成触发条件、挑阈值。理由：① 伤「可证伪」（定义须人可审计可争论，黑箱阈值正是本系统要消灭的）；② 现在信号≈0、回测历史=0，AI 优化不存在的阈值只是过拟合噪声；③ 顺序错——先有明确定义+回测数据，才谈得上让 AI 当「分析师」**建议**新信号或标记失效信号，且永远由人拍板、绝不静默改定义（Phase 2+）。

### 7. 信号册：一信号一档案，承载「可淘汰」

- `docs/signals/` 下一信号一个档案（只追加），骨架：假设 / 可证伪定义+阈值 / 数据源+成本 / 版本历史 / 回测表现 / 生命周期 / 反思复盘。
- 淘汰一个信号时档案不删，只在生命周期段追加「何时淘汰、为何淘汰、学到什么」——这本「试过哪些信号、谁活下来、为什么」的账，是「可淘汰」信条的载体。
- 与 ADR 互补：ADR 记一次性跨层契约/选型；信号档案记每个信号自己的一生。跨信号的大反思可升格为新 ADR。

## 备选方案

- **通用字段渲染配置页**：弃。各信号差异大，通用字段要么塞不下要么一堆空字段，反而难读且易与代码漂移。
- **单一综合市场状态**：弃。合成规则越复杂越难证伪；改为多维独立原子库 + 可选合成层。
- **AI 定阈值/选信号（角色 B）**：弃，见决策 6。
- **二态开关（开/关）**：弃。丢失「观察/影子期先攒回测」这一可证伪最值钱的环节。
- **方法论写进 AGENTS.md**：弃。AGENTS.md 是跨层精简总规则；信号层细节归 ADR（本项目指定的只追加防遗忘装置）。

## 影响

- **信号层 PRD**：各章引用本 ADR，不重述；注册表/卡片/三态/快照活跃集成为 PRD 第 1、5、7 章的地基。
- **账本层**：回填账本 PRD §7.6 快照体量开放问题；快照存储机制需支持「活跃信号集 + 触发时间」。
- **策略层**：只消费「活跃信号集 + 快照 ID」，据此设计消费接口；信号开关状态影响策略可见的信号集。
- **前端**：市场页/配置页按「一信号一张同源 spec 卡片 + 三态开关」实现，沿用视觉契约（ADR-0002）。
- **后续**：`docs/signals/` 信号册约定与「新增一个信号的 checklist」在撰写第一个具体信号时落地，引用本 ADR。
