## 一、项目名称

暂定名：数字资产投资操作系统
内部代号：待定

## 二、项目一句话目标

建设一个面向加密现货投资的研究、策略、执行与复盘工作台，帮助使用者把行情判断结构化、投资假设可验证化、交易行为可追踪化、策略表现可复盘化。

## 三、项目背景

数字资产市场具有 7×24 小时交易、波动大、信息碎片化、叙事变化快、情绪驱动强等特点。个人投资者在参与数字资产投资时，往往不是缺少信息，而是缺少一套稳定的投资工作流。

常见问题包括：

- 行情判断依赖感觉，缺少结构化依据；
- 投资想法很多，但没有沉淀成可验证策略；
- 买入和卖出缺少提前计划，容易受情绪影响；
- 交易后缺少复盘，无法判断盈利来自能力还是运气；
- 不同资产之间缺少统一的仓位管理；
- 长期无法沉淀真正有效的投资方法。

**v0.2 新增认知：这类系统最常见的死法不是功能不够，而是记录中断。** 任何依赖人工持续填表的方案都会在数周内失效。因此本系统的交易数据必须通过交易所 API 自动同步，人只负责决策与确认，不负责抄录。这也是本项目必须做成软件、而不能用表格模板替代的根本原因。

## 四、项目定位

本项目不是 AI 喊单工具，也不是自动交易机器人。

本项目定位为：以加密现货为交易边界，以多资产中长期配置为第一阶段切入点，以行情研判和复盘为核心闭环的数字资产投资操作系统。

与模板化工具（Notion / 飞书表格）的本质区别：

1. **交易数据自动同步**：成交、充提、划转记录由 Binance API 自动拉取，不依赖人工录入；
2. **市场信号数据驱动**：信号由数据规则生成，无主观判断入口；
3. **复盘可自动生成草稿**：周期复盘基于真实数据自动产出，人只做结论确认。

第一阶段具体定义为：**加密现货多资产中长期投资工作台**。

它重点回答：

- 当前加密市场有哪些客观信号正在变化？
- 当前是否适合逐步配置数字资产？
- 哪些资产适合作为核心仓位？哪些只适合观察或卫星仓位？
- 如果要配置，如何分批建仓和控制风险？
- 每一次交易是否符合策略计划？
- 一段时间后，如何判断策略是否有效？

## 五、核心架构理念：策略为第一公民

本系统的核心实体是「策略」。每一个策略都是一个自包含的完整对象，拥有自己的：

| 维度 | 说明 |
| --- | --- |
| 资金上限 | 该策略可动用的最大资金，总资金的定义和约束在策略层完成 |
| 基准（Benchmark） | 每个策略必须指定基准；中长期配置策略的基准建议为「BTC 定投并持有」。若策略长期跑不赢自身基准，策略的复杂度净价值为负，应淘汰 |
| 资产池 | 该策略适用的资产范围（引用全局分层资产池的子集） |
| 验证周期 | 策略有效性的最短验证周期由策略自定义。中长期策略可能需要一个完整市场周期（2–4 年）；执行纪律按周验证，策略有效性按周期验证，两者复盘口径分离 |
| 再平衡规则 | 仓位比例失衡时的处理规则（阈值、频率、方式），由策略自定义 |
| 入场 / 出场 / 加减仓规则 | 结构化定义，可被执行偏离检查引用 |
| 失效条件 | 可证伪的策略淘汰条件 |
| 复盘口径 | 该策略的复盘指标与周期 |
| 版本号 | 见 5.3 |
| 当前状态 | 观察 / 纸面跟踪 / 小仓验证 / 正式运行 / 暂停 / 已淘汰 |

### 5.1 薄全局风险层

策略各自独立，但策略层之上保留一个极薄的全局风险层，只做三条约束：

1. **加密资产总投入上限**：所有策略资金上限之和不得超过此值（与个人总净资产挂钩，数值在 PRD 阶段确定）；
2. **稳定币最低保留比例**：全局底线，任何策略不得击穿；
3. **单资产跨策略合计上限**：防止多个策略不约而同重仓同一资产。

除此之外，一切规则归策略。

### 5.2 仓位归属账本（物理子账户优先）

Phase 1 采用 **1 个实盘策略 = 1 个 Binance 子账户** 的物理隔离模型。成交发生在哪个子账户，就归属该子账户绑定的策略，并绑定成交时生效的策略版本。这样可以把策略归属、对账和复盘的复杂度压到最低。

软件虚拟归属能力仍然保留，但降级为兜底能力：用于外部钱包、系统外交易、绑定前历史成交、异常归属，以及 Phase 2 的纸面策略 / 多策略扩展。无论物理还是虚拟，每一笔成交、每一份持仓都必须能归属到具体策略或明确归入主账户未分配池，否则策略级复盘、基准对比、再平衡全部失真。

这是自动同步交易数据后最核心的数据结构设计，**PRD 阶段优先级最高的设计议题之一**。

### 5.3 策略规则版本化

策略规则被修改后，历史交易必须按交易发生时生效的规则版本进行复盘。因此：

- 策略每次规则变更产生新版本号；
- 每笔交易记录绑定其发生时的策略版本；
- 复盘报告标注所依据的版本。

## 六、项目边界

### 6.1 明确要做（第一阶段）

- 加密现货投资；
- 多资产行情研判（纯数据驱动）；
- BTC 作为市场锚点，BTC / ETH 作为核心资产；
- 少量主流资产作为增强观察，少量赛道资产作为卫星观察；
- 分层资产池；
- 中长期配置策略（第一个策略实例）；
- 分批建仓计划；
- **Binance 交易记录自动同步（含成交、充值、提现、划转）**；
- 组合与策略绩效复盘（含手续费与滑点）；
- 执行偏离观察；
- 站内信号动态与风险提醒（外部 IM 推送延后）；
- 美股和宏观作为后续环境变量。

### 6.2 明确不做（第一阶段）

- 不碰合约、不上杠杆、不做做空、不做期权；
- 不做高频交易、不做套利；
- 不做自动下单；
- 不做 DeFi 借贷、质押、LP；
- 不做美股交易；
- 不做代客理财、不做喊单社区、不承诺收益；
- 不做全市场垃圾币扫描；
- 不做面向外部用户的商业化产品；
- **不做税务处理**（报税由系统外的统一途径解决，但交易数据可导出以备外部使用）；
- **不做主观情绪识别 / 心理分析**（以客观执行偏离观察替代）。

## 七、美股边界

美股只看不买。系统关注美股和宏观环境，用于辅助判断加密市场风险偏好，但不把美股作为交易标的。

可观察内容：纳指、标普；美元指数；美债收益率；市场 risk-on / risk-off 状态；Coinbase、Strategy、矿企等加密相关股票；BTC / ETH ETF 资金流；重要宏观事件。

原则：**交易资产范围要窄，信息观察范围可以适度放宽。** 美股数据只需 high-level 级别，数据源相对简单（见第十一节）。

## 八、资产边界

资产池采用分层管理，作为全局共享资源，各策略引用其子集。

- **T0：现金 / 稳定币** —— 防守、等待机会、控制回撤。注意稳定币本身存在风险分层（USDT / USDC 等），需在 PRD 阶段确定选型与分散规则；
- **T1：核心资产** —— BTC、ETH。BTC 是市场锚点，ETH 是核心生态资产；
- **T2：主流高流动性资产** —— 如 SOL、BNB 等，可作为增强收益资产，仓位低于核心资产；
- **T3：赛道代表资产** —— AI、RWA、DeFi、L2、基础设施、稳定币生态、交易所生态等，第一阶段以观察和小仓位验证为主；
- **T4：高风险资产** —— Meme、小市值、事件币、短期热度币，第一阶段只允许观察、纸面跟踪或极小仓位验证。

每个入池资产记录：名称、层级、赛道、入池理由、与 BTC / ETH 的关系、当前强弱状态、是否允许真实买入、最大允许仓位、退出条件。

## 九、市场信号研判原则

市场信号研判是闭环的起点，遵循以下硬性原则：

1. **无主观判断入口**：一切信号取值由数据规则得出，系统不提供"我觉得现在是熊市"式的人工覆写；
2. **信号必须有可证伪定义**：每个信号原子（如 BTC 趋势结构、ETH/BTC 强弱、资金费率情绪）必须由明确的数据条件定义。综合状态标签（如防守 / 观察 / 试探 / 分批配置）不属于 Phase 1，若未来需要，只能作为信号原子之上的可选合成层；
3. **决策时点快照（point-in-time snapshot）**：每次生成信号取值时，将当时实际消费的输入数据原样存档。这是信号可证伪、复盘无后视镜偏差、未来可回测的前提，**属于 day one 必须做对的数据架构决策**；
4. **信号切换需定义频率与滞后容忍**：避免信号抖动导致频繁切换；
5. **站内信号动态优先**：Phase 1 在市场页内呈现信号切换、风险提醒与取数异常；Telegram / 飞书等外部推送通道不属于 Phase 1，待骨架跑通后再评估。

研判输入维度（Phase 1）：BTC / ETH 趋势结构、ETH 相对 BTC 强弱、资金费率情绪、持仓量、多空比，均优先来自 Binance 公开行情与公开衍生品数据。ETF 资金流、美股 / 宏观、社交情绪、链上数据等非 Binance 数据源延后。

## 十、AI 角色边界

第一阶段 AI 的适用范围明确收窄为三类：

1. **市场情绪读取**：阅读低成本 / 免费公开文本源，输出结构化情绪信号；X、CoinMarketCap 等付费或不稳定来源延后评估；
2. **文字处理**：研报摘要、信息整理、复盘报告草稿润色；
3. **投资策略研究辅助**：学习与消化投资策略论文、方法论资料。

明确不用于：数据分析计算、交易执行、价格预测。

**AI 信号同样受复盘约束**：AI 输出的情绪信号必须被记录、标注来源，并定期回测其准确率。AI 不能成为系统中唯一不被复盘检验的模块（呼应原则 12.5）。AI 判断与数据规则信号在界面与存储中严格区分标记。

## 十一、数据源规划（待调研清单）

| 类别 | 候选来源 | 备注 |
| --- | --- | --- |
| 行情与交易数据 | Binance API（行情、K 线、成交、账户、充提划转） | Phase 1 第一优先；行情与账户分属信号层 / 账本层 |
| Binance 衍生品公开数据 | Binance funding / open interest / long-short ratio | Phase 1 仅只读公开数据，不交易合约、不接交易权限 |
| 市场情绪 | 免费新闻 / 公告源；CoinMarketCap、X 等待评估 | Phase 1 延后；后续先以观察态接入，不进入交易执行 |
| ETF 资金流 | 待调研（Farside 等公开来源） | Phase 1 延后 |
| 链上数据 | 待调研（Coinglass、Glassnode 等） | Phase 1 延后，评估免费层与付费成本 |
| 美股与宏观 | 待调研 | Phase 1 延后；未来只需 high-level 数据 |

数据源可行性是模块一能否落地的前提。Phase 1 先只看 Binance 源的数据；其它来源作为后续扩展调研。每个研判维度需明确：对应数据源、免费或付费、拉取方式与频率。

## 十二、绩效测量原则

1. **手续费与滑点计入复盘**：成交记录同步时保留手续费字段，滑点按计划价与成交价之差计算；
2. **收益率方法**：存在持续追加 / 撤出资金时，简单收益率失效。系统采用时间加权收益率（TWR）衡量策略能力，资金加权收益率（MWR）衡量实际资金效果，两者并列展示；
3. **充提划转必须入账**：否则收益率计算失真；
4. **策略对基准**：每个策略的绩效永远与其自身基准并列展示；
5. **执行偏离观察**（替代情绪化识别）：客观记录每笔交易相对策略规则的偏离——是否偏离计划价格区间、计划仓位、计划时点；交易频率是否异常。只做客观标记，不做心理归因。

## 十三、终局设想

长期建设为完整的数字资产投资操作系统，覆盖四个核心能力：

- **行情研判**：从价格趋势、市场结构、交易所数据、衍生品情绪等角度识别市场信号；宏观环境、ETF 资金流、链上数据、新闻事件等非 Binance 输入延后。目标不是资讯聚合，而是可复盘的信号识别；
- **策略管理**：多策略共存（中长期配置、趋势、回调、叙事轮动、事件驱动、防守），每个策略按第五节定义结构化管理；
- **绩效跟踪与复盘**：跟踪市场判断正确性、资产选择、仓位分配、执行纪律、策略存废；
- **交易执行**：从手动执行辅助，逐步到半自动执行，再到有限自动化执行。第一阶段不接自动下单。

## 十四、第一阶段 MVP

### 14.1 MVP 定位与行走骨架

第一阶段 MVP 是加密现货多资产中长期投资工作台，以**行走骨架（walking skeleton）**方式交付：先打通最细的端到端闭环，再加宽。

行走骨架 = Binance 只读 API 同步 + Binance 源市场信号原子 v0 + 一张中长期配置策略卡 + 自动生成周复盘草稿。

**硬时间盒：6–8 周。骨架跑通之前，不增加任何功能。**

### 14.2 MVP 闭环

市场信号研判 → 多资产观察池 → 中长期配置策略 → 分层仓位计划 → 手动下单（Binance）→ 交易自动同步与策略归属 → 组合 / 策略绩效复盘 → 调整资产池和策略规则（产生新版本）

### 14.3 MVP 核心模块

**模块一：市场信号研判**
按第九节原则输出多维信号原子的当前取值（如 BTC 趋势结构、ETH/BTC 强弱、资金费率情绪），每次输出附带决策时点快照。Phase 1 在站内呈现信号动态，不接外部 IM 推送。

**模块二：多资产观察池**
维护分层资产池（见第八节）。

**模块三：中长期配置策略卡**
第一阶段实例化一个策略：加密现货多资产中长期配置策略。按第五节策略对象结构定义，基准为 BTC 定投并持有。

**模块四：分层仓位计划**
在策略资金上限内明确：稳定币最低保留比例、核心资产目标仓位、卫星资产总仓位上限、单资产最大仓位、单赛道最大仓位、高风险资产总仓位上限、首笔建仓比例、后续加仓条件、暂停加仓条件、再平衡规则。
原则：核心资产可以重，卫星资产必须轻，高风险资产只能试验。

**模块五：交易同步与归属**
- 通过 Binance 只读 API 自动同步成交、充值、提现、划转记录；
- 每笔成交通过物理子账户绑定归属到策略，并绑定策略版本；外部 / 异常交易走虚拟归属兜底；
- 自动关联交易发生时的市场信号快照；
- 记录手续费；按计划价计算滑点；
- 标记执行偏离（偏离计划价格区间 / 仓位 / 时点）；
- 人工仅需补充「执行理由」等少量决策上下文，以及录入系统外（如外部钱包）发生的交易。

**模块六：组合与策略绩效复盘**
- 周复盘：执行纪律、执行偏离、市场信号变化（系统自动生成草稿，人工确认结论）；
- 月复盘：策略与组合表现；
- 季度及以上：按各策略自身验证周期评估有效性（注意：中长期策略的有效性结论可能需要完整市场周期，季度复盘只评估「是否按规则运行」，不轻易下「策略有效 / 无效」结论）。

复盘指标：TWR / MWR、相对策略基准表现、相对 BTC 及 BTC/ETH 组合表现、最大回撤、稳定币占比变化、核心 / 卫星资产贡献、单资产盈亏、手续费与滑点损耗、执行偏离次数与幅度、AI 情绪信号准确率回测、是否需要调整资产池或策略规则。

## 十五、MVP 成功标准

第一阶段是否成功，不以短期收益为唯一标准，而以闭环是否跑通为标准：

1. 行走骨架在时间盒内上线运行；
2. 市场信号原子稳定生成，且每个启用信号有可证伪定义与时点快照；
3. 维护一个清晰的分层资产池；
4. 每次交易前有明确的策略和仓位计划；
5. 交易记录 100% 由系统自动同步，无人工抄录；
6. 每周复盘草稿自动生成，人工确认完成率达标；
7. 能看清组合收益来自哪些资产，并与策略基准对比；
8. 能判断卫星资产是否真的贡献了超额收益；
9. 能客观识别执行偏离；
10. 复盘结果实际改变过资产池或策略规则（闭环真正反哺决策）；
11. 避免无计划、无边界、无复盘的随意交易。

## 十六、项目关键原则

1. **先闭环，后扩展**：不追求功能完整，追求闭环完整；
2. **先手动，后自动**：自动化先发生在数据同步、信息整理、提醒、记录和复盘上，不发生在真实下单上；
3. **先中长期，后短周期**：第一阶段优先支持中长期配置；
4. **先资产分层与策略骨架，后策略扩展**：先跑通策略对象模型、物理子账户归属 / 虚拟兜底和复盘口径，再扩展更多策略类型；
5. **先复盘能力，后预测能力**：系统的核心不是预测价格，而是让判断可验证、策略可淘汰、行为可复盘——**包括 AI 信号在内，系统中不存在不被复盘检验的模块**；
6. **先只读，后交易权限**：Phase 1–3 仅使用只读 API 密钥（无交易、无提现权限）。交易权限的引入推迟到 Phase 4，并需单独的安全方案评审。

## 十七、阶段规划

**Phase 1：中长期配置 MVP（行走骨架，6–8 周时间盒）**
交付物：Binance 只读同步管道；物理子账户归属 + 虚拟兜底 v0；Binance 源市场信号原子 v0（含快照机制）；分层资产池；中长期配置策略卡（含基准对比）；仓位计划；自动周复盘草稿；站内信号动态；基础风险规则（薄全局风险层）。

**Phase 2：策略模块扩展**
从单一策略扩展到多策略管理。可能新增：趋势、回调、事件驱动、叙事轮动、防守策略。
交付物：策略假设库；策略状态流转；策略版本化机制完善；策略专属复盘模板；策略级风险规则；纸面跟踪机制；小仓验证机制；多策略下的虚拟归属兜底完善。

**Phase 3：智能复盘与风险提醒**
交付物：自动归因；执行偏离深度分析；仓位异常提醒；市场风险升高提醒；策略失效提醒；组合相关性分析；AI 情绪信号准确率体系化回测。

**Phase 4：半自动执行辅助**
前提：完成交易权限 API 密钥的安全方案评审。
交付物：条件触发提醒；交易计划生成；仓位建议；止损止盈提醒；人工确认执行；执行后自动记录。

**Phase 5：有限自动化执行**
仅对成熟、低风险、规则明确的策略开放。
前提：策略已长期验证；风控规则稳定；资金权限隔离；人工干预与熔断机制；完整审计日志。

## 十八、安全与权限

1. API 密钥分级：Phase 1–3 只读密钥；交易权限密钥的申请、存储、轮换方案在 Phase 4 前单独设计；任何阶段不持有提现权限；
2. 密钥与敏感配置不入代码库，使用独立的密钥管理方案；
3. 数据备份：交易账本与时点快照为不可丢失数据，需备份策略；
4. 站内动态 / 未来推送仅发送信号与提醒，不包含可被利用的账户敏感信息。

## 十九、项目预算与项目级失效条件

### 19.1 预算（PRD 阶段量化）

- 时间预算：每周可投入的开发与运营小时数；
- 资金预算：数据源订阅费（X API、链上 / 衍生品数据付费层）、服务器与基础设施成本；
- 预算超限本身是一个需要复盘的信号。

### 19.2 项目级失效条件

计划书要求每个策略都有失效条件，项目自身同样需要：

1. 行走骨架超过时间盒（6–8 周）仍未跑通端到端闭环 → 暂停开发，重新评估范围；
2. 系统运行 6 个月后，复盘结论从未实际改变过任何一次决策（资产池、仓位规则、策略规则均无调整）→ 系统未产生真实价值，重新评估存续；
3. 开发投入持续挤占投资研究与决策本身 → 系统成为拖延载体，强制收缩范围。

## 二十一、阶段性结论

本项目具备建设价值，且因「交易数据自动同步 + 数据驱动研判」两个特性，必须以自研软件形态落地，模板化工具无法替代。

第一阶段最合理的落地方向是：以行走骨架方式，在硬时间盒内建设一个加密现货多资产中长期投资工作台。它以 BTC 为市场锚点，以 BTC / ETH 为核心资产，以少量主流资产和赛道资产作为卫星观察对象，通过 Binance 源数据驱动的信号研判、策略化的分批配置、自动同步的交易记录和自动生成的组合复盘，完成最小投资闭环。

项目的核心价值不是预测价格，而是：

**让投资判断结构化，让交易行为可追踪，让策略表现可验证，让复盘结果能反哺下一轮决策——并且系统中的每一个模块（包括 AI）都接受同样的复盘检验。**
